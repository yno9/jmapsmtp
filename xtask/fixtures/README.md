# Test fixtures

**Every private key in this directory is public. Never reuse one for
anything.** They are committed on purpose and have been pushed to a public
repository; treat them as known to the world.

## Why they are committed

The differential harness seeds both sides — the Go oracle and this port — from
the same directory before comparing them. Three of the files here would
otherwise be generated at first boot, differently on each side:

| File | Generated by | Why seeding it matters |
|---|---|---|
| `dkim-key.pem` | `dkim::load_or_generate_key` | Two different keys produce two different `DKIM-Signature` headers, so every outbound message would differ and the comparison would be meaningless |
| `smtp-tls-cert.pem`, `smtp-tls-key.pem` | `inbound_tls` | A self-signed cert generated per boot differs in its serial and validity dates |
| `setup.token` (written by the fixture, not stored here) | startup | Random per account |

Seeding them is preferred over filtering them out afterwards: every
normalisation filter is a place a real difference could hide (see
`xtask/src/difftest/fixture.rs`).

The PGP fixtures are used by the interop suites rather than the harness:

| File | Used by |
|---|---|
| `pgp-private.asc` / `pgp-public.asc` | `pgp_interop`, `wkd_interop` — the account's own key |
| `pgp-public-relay.asc` | `wkd_interop` — the relay-wide key, **deliberately different** from the account's, so "served the user's key" and "served the relay's key" are distinguishable. One shared fixture made that assertion vacuously true and hid SPEC.md §11.15 |

## Why publishing them is not a leak

- The TLS cert is self-signed for `mail.example.com`, a reserved domain
  (RFC 2606). It cannot be presented as a valid certificate for a real host,
  and inbound STARTTLS is opportunistic and unauthenticated regardless.
- The PGP key's only identity is
  `Interop Test (throwaway key for cross-implementation tests) <interop@example.com>`.
- A DKIM private key has power only where DNS publishes the matching public
  key. No domain does, and the `dkim-dns.txt` that would make one authoritative
  is not committed.

None of them reach a shipped binary: they are referenced from `#[cfg(test)]`
modules and from `xtask`, which is a development tool.

## If you need a new fixture

Generate it, add it to `.gitignore` **by name**, and say here what it is for.

The un-ignore rules are per-file on purpose. `*.pem`, `*.key` and `*.asc` are
all ignored repository-wide, and each of the six files above is exempted
individually; a directory-wide `!xtask/fixtures/*.pem` would exempt the *next*
file too, and a real key dropped here would be committed by the following
`git add -A` without a word.

`.asc` is in that list because an exported OpenPGP private key is armoured and
looks exactly like `pgp-private.asc`. It was missing at first, and the check
that caught it is worth repeating after any change here:

```sh
touch xtask/fixtures/probe.asc && git check-ignore -v xtask/fixtures/probe.asc; rm xtask/fixtures/probe.asc
git check-ignore -v xtask/fixtures/pgp-private.asc   # must print nothing
```

The first must report a match, the second must not.
